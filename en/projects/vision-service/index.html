The problem
Experiment scripts often rely on local paths and manual steps. A usable model service needs explicit input limits, task states, failure feedback, and a way to compare results.
The approach
  1. Validate image type, dimensions, and size before creating a traceable task.
  2. Run inference through a fixed model adapter, recording configuration, duration, and failures; keep classical filters as baselines.
  3. Provide input/output comparisons and exportable reports with model versions and run records.
Existing artifacts
  • Twelve service tests pass; real model outputs match direct inference element for element.
  • Input limits, task queues, a real SHINE CPU model, access isolation, and result downloads are implemented.
  • Real HTTP and fresh-environment migration checks pass; public-load and model-quality evaluations remain open.
Findings & limitations
Research models require separate evaluation for other image domains. A completed first version must include real model inference rather than a filter-only demo. Real-time speed will depend on measured performance.
What comes next
  • Establish domain-specific quality benchmarks before adding more complex vision tasks.
  • Extend retry, retention and capacity evaluation for the deployment target.
  • Verify cross-machine migration and public deployment.
