The problem
Fluent answers alone are not enough for engineering use; sources need to be verifiable. Scattered documentation and experiment records also require a clear distinction between written evidence, run states, and model inferences.
The approach
  1. Index permitted technical documents and attach verifiable passages and sources to answers.
  2. Accept open-ended questions, state when evidence is insufficient, and query experiment or task states through read-only tools.
  3. Evaluate answerable, unsupported, and injection-style questions; record quality, latency, and API cost.
Existing artifacts
  • Retrieval, source versioning, read-only queries and an optional model adapter are implemented.
  • Nineteen service tests cover citation validation, atomic budgets and request recovery.
  • Retrieval-only is the default; live provider acceptance still requires an external account.
Findings & limitations
Document text must not become an execution instruction. The assistant will not expose arbitrary commands or write tools. Citation relevance, unsupported-answer handling, and cost require measurement.
What comes next
  • Expand the published bilingual corpus and retrieval evaluation coverage.
  • Connect a real provider and verify answer grounding and actual billing.
  • Verify public access controls and migration across machines.
